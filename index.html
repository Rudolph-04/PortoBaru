About

I'm an Information Systems student in my sixth semester, concentrating in Smart Application Supporting Information Systems.

The part I enjoy most happens before the code: mapping how a process runs today, spotting where time gets wasted, and turning that into a clear set of roles, features, and screens. Then I build it.

So far that has meant child health records for a posyandu, a booking and payment system for a PlayStation rental, and sales tracking for a small snack business.

How I work

Good software starts with understanding the job it replaces.

  1. 01

    Observe

    Talk to the people doing the work and look at how it runs today: paper forms, spreadsheets, chat groups.

    Interviews · field notes
  2. 02

    Model

    Turn the process into use case, activity, and ER diagrams so everyone agrees on what the system must do.

    Use case · activity · ERD
  3. 03

    Design

    Define user roles, features, and screens. Decide what to automate and what stays manual.

    Roles · features · wireframes
  4. 04

    Build & test

    Ship a working version, run it against real data, and fix what breaks.

    Code · real data · fixes
